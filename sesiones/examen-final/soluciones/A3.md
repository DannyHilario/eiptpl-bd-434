## Consulta 1 — Top 5 cuentas con mayor saldo actual

**Pregunta:** ¿Cuáles son las 5 cuentas con el mayor saldo actual? Muestra el número de cuenta, el tipo de cuenta y el saldo actual. Ordena de mayor a menor saldo.

```sql
SELECT TOP 5 CU.NumeroCuenta, CU.TipoCuenta,
    CU.SaldoActual
FROM Cuenta AS CU
ORDER BY CU.SaldoActual DESC
```

**Explicación:**

- `SELECT TOP 5` — limita el resultado a las primeras 5 filas después de aplicar el ordenamiento. En SQL Server, `TOP` siempre trabaja junto con `ORDER BY`; de lo contrario, las 5 filas serían arbitrarias.
- `ORDER BY CU.SaldoActual DESC` — ordena de mayor a menor saldo **antes** de que `TOP 5` recorte el resultado. Sin `DESC`, se obtendrían las 5 cuentas con el saldo *más bajo*, que es lo contrario a lo pedido.
- No se necesita `WHERE` porque no hay ningún filtro: se quieren todas las cuentas, solo que limitadas a las primeras 5 del ranking.

**Error frecuente:** Escribir `TOP 5` sin `ORDER BY` o con `ORDER BY ASC` produce un resultado incorrecto.

## Consulta 2 — Transacciones con monto mayor a $5,000

**Pregunta:** Genera un reporte de las transacciones con monto mayor a $5,000. Muestra nombre del cliente, apellido paterno, número de cuenta, tipo de transacción, monto y fecha. Ordena de mayor a menor monto.

```sql
SELECT C.Nombre, C.PrimerApellido,
    CU.NumeroCuenta, T.TipoTransaccion,
    T.Monto, T.FechaTransaccion
FROM Transaccion AS T
    INNER JOIN Cliente AS C ON C.idCliente = T.idCliente
    INNER JOIN Cuenta AS CU ON CU.idCuenta = T.idCuenta
WHERE T.Monto > 5000
ORDER BY T.Monto DESC
```

**Explicación:**

- `FROM Transaccion AS T` — la tabla principal es `Transaccion` porque contiene el monto y el tipo de movimiento.
- `INNER JOIN Cliente AS C ON C.idCliente = T.idCliente` — para mostrar el nombre del cliente se conecta la tabla `Cliente` usando `idCliente` como columna en común.
- `INNER JOIN Cuenta AS CU ON CU.idCuenta = T.idCuenta` — para mostrar el número de cuenta se conecta `Cuenta` usando `idCuenta`.
- `WHERE T.Monto > 5000` — el operador `>` es exclusivo: no incluye transacciones de exactamente $5,000. Si el enunciado dijera "mayor o igual", se usaría `>=`.
- `ORDER BY T.Monto DESC` — la transacción de mayor monto aparece primero.

**Por qué 6 columnas en el SELECT:** El enunciado pide específicamente `TipoTransaccion`, que no aparecía en las versiones A1 y A2. Hay que leer con cuidado qué columnas se solicitan en cada versión.

## Consulta 3 — Clientes sin ninguna transacción

**Pregunta:** ¿Qué clientes no han realizado ninguna transacción? Muestra nombre, apellido paterno y correo electrónico. Ordena por apellido paterno.

```sql
SELECT C.Nombre, C.PrimerApellido,
    C.CorreoElectronico
FROM Cliente AS C
    LEFT JOIN Transaccion AS T ON T.idCliente = C.idCliente
WHERE T.idTransaccion IS NULL
ORDER BY C.PrimerApellido
```

**Explicación:**

- `LEFT JOIN Transaccion AS T ON T.idCliente = C.idCliente` — el `LEFT JOIN` incluye **todos** los clientes en el resultado, aunque no tengan transacciones. Para los clientes sin movimientos, todas las columnas provenientes de `Transaccion` quedan como `NULL`.
- `WHERE T.idTransaccion IS NULL` — detecta los clientes que no tuvieron coincidencia en `Transaccion`. `IS NULL` es obligatorio; escribir `= NULL` no funciona en SQL porque los nulos no se comparan con `=`.
- `ORDER BY C.PrimerApellido` — ordena alfabéticamente en sentido ascendente por apellido paterno.

**El patrón `LEFT JOIN` + `WHERE IS NULL`:** Es la forma estándar de detectar "ausencias" en SQL sin usar subconsultas. La lógica es: "traer todo de la izquierda, y quedarse solo con lo que no encontró pareja a la derecha".
